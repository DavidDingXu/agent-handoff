# 新增其他智能体

[English](adding-agent.md) | 简体中文

agent-handoff 目前支持 Codex 和 Claude Code 作为来源端与目标端。新增智能体
本质上是增加适配器，不是另造一种捆绑包格式：v2 捆绑包已经支持按智能体名称
保存原生会话，并用中立转录承担跨智能体导入。

下文用 `acme` 作为示例智能体名称。

## 兼容性契约

一个适配器必须同时满足两种不同保真级别：

| 方向 | 必须达到的结果 |
| --- | --- |
| acme -> acme | 保留原生会话结构与内容，但生成全新的任务身份和目标路径。 |
| acme -> 其他智能体 | 把可见对话、工具证据、图片和元数据转换为中立转录。 |
| 其他智能体 -> acme | 把中立转录恢复为 Acme 能查询、能继续的原生任务。 |

不要把来源端私有字段硬塞进另一个智能体的状态，也不要把语义转换宣传成原生结构
高保真。

如果只是新增一个按智能体分目录的原生会话，通常不需要升级捆绑包版本。修改中立
schema、manifest 含义、完整性规则或其他不兼容契约时，必须评估格式升级，并保留
旧版本读取路径。

## 1. 注册智能体名称

修改 `internal/bundle/format.go`：

1. 增加 `AgentAcme` 常量。
2. 加入 `SupportedAgents`。
3. 确认 `IsSupportedAgent` 能识别它。

规范名称使用稳定的小写形式。它会出现在 manifest、JSON 输出、捆绑包内原生会话
路径、命令参数和导入 ledger 中，发布后不要随意改名。

## 2. 实现原生适配器

新增 `internal/acme/`。可以参考 Codex 和 Claude 包的职责边界，但必须按 Acme 的
真实存储契约建模，不能照抄其中一个实现。

这个包要为 CLI 提供以下能力：

- 按“显式参数、Acme 专用环境变量、平台默认值”的顺序解析 Acme home；
- 发现当前会话，并能按显式 session ID 定位会话；
- 读取原生会话，以及可获取的标题、工作目录、时间、模型、git 元数据和引用图片；
- 在不执行命令、不抓取会话内 URL 的前提下转换成 `neutral.Transcript`；
- 同智能体导入时用新身份恢复原生会话；
- 跨智能体导入时把中立转录恢复为 Acme 原生任务；
- 只追加让新任务可见所需的最少 index/state 数据；
- 通过 Acme 的真实状态验证导入任务可查询。

每条写入路径都要像现有适配器一样保留备份。不能通过改写已有任务来伪装成导入。

## 3. 接入 CLI

修改 `internal/cli` 中的显式路由点：

- `cli.go`：`--source`、`--target`、帮助文本、来源探测和 Acme 宿主环境标识；
- `share.go`：导出路由、原生会话收集、中立转换；如果 Acme 事件结构不同，还要
  接入对应的密钥扫描；
- `import.go`：目标 home、同智能体判断和原生恢复路由；
- `preview.go`、`detail.go`、`verify.go`：来源专用展示或校验分支。

适配器数量还少时保留显式 switch 更容易审计。只有第三个实现证明存在稳定公共
接口、并且注册表确实能消除有效重复时，才抽取通用 adapter registry。

自动探测只是便利能力，不能成为隐式前提。显式 `--source acme`、
`--target acme` 必须始终有效并拥有更高优先级。

## 4. 更新面向智能体的工作流

按需修改 `skills/agent-handoff/SKILL.md` 和插件元数据：

- 把 Acme 加入支持的交接方向；
- 说明如何判断技能正运行在 Acme 中；
- Acme 有原生问答工具时，把交互式选择映射到该工具；
- 只有 Acme 的插件文件解析方式不同时，才增加新的二进制定位规则；
- 保留“先 preview、再显式确认 import”的流程。

技能本身不要解析或改写会话存储；原生状态知识只能放在 Go 适配器中。

## 5. 覆盖完整测试矩阵

适配器单元测试必须使用临时 home 下的合成会话，重点覆盖：

- macOS、Linux、Windows 路径下的 home 和当前会话解析；
- 原生记录解析、元数据、图片和畸形记录；
- 同智能体新身份改写与原生事件保真；
- 双向跨智能体中立转换；
- 只追加 index/state、备份、重复导入与 verify；
- 密钥扫描和不可信内容边界；
- 显式来源/目标覆盖与当前宿主自动探测；
- 包含新原生会话目录的捆绑包写入/读取往返。

把 `internal/integration_test` 从当前四个方向扩展到相关的 N x N 矩阵。最低要求是
`acme -> acme`、所有已有来源到 Acme，以及 Acme 到所有已有目标。如果 Acme 也有
插件宿主，CI 还要在隔离 home 中增加真实插件安装冒烟测试。

运行：

```sh
go test ./... -count=1 -race
go vet ./...
make cross VERSION=v<version>

cd deploy/worker
npm ci
npm test
```

只有平台 CI 全绿，而且 README、中英文文档、命令帮助、技能行为和 changelog 对支持
边界的说法完全一致，这个 PR 才算完成。
