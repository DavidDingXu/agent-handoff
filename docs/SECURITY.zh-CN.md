# 安全策略

[English](../SECURITY.md) | 简体中文

## 支持版本

只有最新 `main` 与最近一个 tag 版本会收到安全修复。

## 报告漏洞

**请不要通过公开 GitHub issue 报告漏洞。**

请直接邮件联系维护者（联系方式见仓库所有者主页），或在本仓库通过 *Security → Report a vulnerability* 提交 GitHub 安全公告。请包含：

- 涉及的组件（CLI、捆绑包格式、链接服务 worker），
- 最小复现或 PoC，
- agent-handoff 版本（`agent-handoff version`）与操作系统。

你应在 72 小时内收到回复。修复发布后，除非你希望匿名，我们会在 changelog 中致谢。

## 安全属性

agent-handoff 天生处理敏感材料 —— 完整的智能体会话记录。以下是我们承诺并有测试保障的属性：

- **链接载荷端到端加密。** AES-256-GCM，客户端生成 256 位密钥；密钥只随 URL fragment 传输，不会抵达存储供应商或自建存储 API。fragment 不会进入发往 resolver 的 HTTP 请求；但浏览器打开页面后，页面脚本能够读取 fragment，因此应使用内置的已审查页面或你信任的 resolver。
- **密钥扫描拦截导出。** 高置信模式（OpenAI/Anthropic/AWS 密钥、GitHub token、私钥块、bearer JWT）命中即阻断分享，直到用户显式传 `--include-secrets` 放行。
- **捆绑包防篡改。** 每个条目都有 SHA-256 校验；`import --execute` 在写入任何内容前先验证校验和。
- **捆绑包解压有硬上限。** 条目超过 1024 个、单条目超过 128 MiB，或总解压内容超过 256 MiB 时，读取方会在导入写入前拒绝该压缩包。
- **导入只追加。** agent-handoff 绝不修改或删除已有智能体状态；写入的每个文件旁边都留备份，且绝不执行、不主动抓取分享会话里的任何内容。
- **导入内容是不可信数据。** 捆绑包内的任何东西（命令、URL、工具输出）都不会被自动执行。

## 已知局限

- 分享链接本身就是解密凭证。任何拿到完整 URL（含 `#h=` 或 `#k=` fragment）的人都能解密载荷；请通过你信任的渠道发送链接。
- 匿名存储供应商能看到上传/下载 IP、时间、大小和 User-Agent。它们只收到密文，但可用性和实际删除时间不受本项目控制。
- 项目运营的 Worker 与匿名后备池都是尽力而为服务，不是持久存储或 SLA。需要可控可用性时，请用自建 endpoint 或 zip 文件。
- 密钥扫描是高置信设计，并不穷尽 —— 非标准或自定义格式的密钥可能漏检。
